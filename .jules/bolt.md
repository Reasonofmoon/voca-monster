## 2025-06-07 - O(1) Index Lookup and Regex Escaping Learnings
**Learning:** In `App.tsx`'s `AnalyzedContent`, I discovered two key things: 1) Using `String.prototype.split` with a capturing group regex generates an array where odd indices are guaranteed to be the exact matched groups. This allows replacing an O(N) lookup (`highlightWords.some(...)`) with an O(1) index check (`index % 2 === 1`). 2) Refactoring string escaping logic via Git diff can easily introduce invalid regex flags if backslashes aren't handled perfectly, so it's safer to leave existing tested escaping sequences untouched unless fixing a bug.
**Action:** When mapping over split string fragments, use mathematical index properties for identification instead of array searches whenever possible. Also, avoid unnecessary "fixes" to regex escaping strings during unrelated refactoring to prevent syntax errors.
