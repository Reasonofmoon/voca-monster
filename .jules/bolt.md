## 2024-06-06 - [AnalyzedContent Performance Optimization]
**Learning:** Found a specific bottleneck in `AnalyzedContent` component parsing using `Array.some` to check if a string slice matched any of the highlighted words inside a split `.map()` iteration causing O(M*N) performance string parsing. Because the component uses `String.prototype.split` with a capturing group regex `/(words|here)/gi`, the split strings contain exactly the matches in the odd indices `(index % 2 === 1)`, allowing string matching to be dropped entirely for an O(1) detection per slice.
**Action:** Always leverage capturing group indices `(index % 2 === 1)` when iterating over `String.prototype.split` with regex capturing groups instead of re-evaluating matches within the slice mapping. Also wrap such computationally expensive text rendering components with `React.memo` and use `useMemo` for any complex regex constructions.
