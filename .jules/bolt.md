## 2025-06-17 - [Optimizing Regex Matches Retrieval with Splitting Strategy]
**Learning:** O(N) array searching inside iterative rendering over text chunks (`highlightWords.some(...)`) becomes computationally heavy, especially during state shifts. Utilizing Javascript `String.prototype.split` with a capturing group regex guarantees target matches populate odd indices, offering an immediate O(1) identification check (`index % 2 === 1`). Furthermore, directly modifying/fixing string replacements for regex escapes (e.g. `[-\/\\^$*+?.()|[\]{}]`) to avoid eslint warnings or "better structure" without absolute certainty leads to runtime syntax errors like `Invalid regular expression`.
**Action:** When mapping over split string results using a capturing regex, replace lookup iteration mechanisms like `includes` or `some` over match terms with a direct modulus-based index verify to ensure O(1) efficiency. Do not blindly change string escapes within `RegExp` unless necessary.
