## 2026-04-08 - [Regex Optimization Risk: Preserving Escape Sequences in Replace Tools]
**Learning:** When refactoring regex patterns that process strings containing special characters, using string replacement tools can be exceptionally dangerous due to unintended double-escaping (e.g., transforming `[\]` into `[\\]`). This breaks the regex literal's internal parsing and fails completely when an unescaped special character is encountered in input, creating immediate, silent runtime syntax errors that aren't caught by the compiler.
**Action:** When performing `replace_with_git_merge_diff` near a `new RegExp(...)` creation, strictly copy the original regex structure exactly without modifications to character escapes. Before pushing string refactoring, explicitly test the new regex string with edge-case characters directly in the node terminal to verify it compiles.
